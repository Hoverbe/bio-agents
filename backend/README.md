## 1. 系统概述

Bio-Agent 是一个面向生物公司的内部智能助手系统，部署在公司内网 Linux 服务器上。系统通过多个专业 Agent 协同工作，为科研人员提供以下核心能力：

| 功能 | 说明 |
|------|------|
| **基础问答** | 生物学知识、实验 protocol、公司 SOP 等问答 |
| **MCP 服务连接** | 对接公司内部 MCP Server（数据库、LIMS、实验系统等） |
| **流程化 Skill** | 预定义的实验流程、数据分析流程、报告生成等 |
| **自动化脚本执行** | 生成并执行 Python/R 脚本，处理用户定制化需求 |
| **文件上传处理** | 支持文本、PDF 等文件的上传、解析和基于内容的问答 |

## 3. Agent 职责详解

### 3.1 主控 Agent（Orchestrator Agent）

**核心职责**：系统的"大脑"，负责任务分发和流程编排

| 功能 | 说明 |
|------|------|
| **意图识别** | 判断用户是要"问答"、"调用工具"、"执行自动化"还是"混合任务" |
| **任务路由** | 将请求分发给对应的下游 Agent |
| **流程编排** | 处理多步骤任务（如：先查文献 → 再分析数据 → 最后生成报告） |
| **会话管理** | 维护上下文、处理追问、管理长对话 |
| **安全管控** | 敏感操作（如执行代码）需要确认，防止误操作 |

**为什么单独一个 Agent？**
- 避免每个 Agent 都重复做意图判断
- 统一管控权限和流程
- 支持复杂的多 Agent 协作流程

---

### 3.2 问答 Agent（Q&A Agent）

**核心职责**：所有知识型、对话型任务

| 功能 | 说明 |
|------|------|
| **基础问答** | 生物学知识、实验 protocol、公司 SOP 等 |
| **文献检索** | 对接 PubMed、公司文献库等 |
| **文档问答** | 基于上传的 PDF/文本做 RAG 问答 |
| **多轮对话** | 追问、澄清、总结 |

**技术要点**：
- 需要 RAG 架构（向量数据库 + 重排序）
- 支持长文本（PDF 可能几百页）
- 可对接外部知识库 MCP

---

### 3.3 工具/流程 Agent（Tool & Skill Agent）

**核心职责**：封装和执行业务流程（Skill）

| 功能 | 说明 |
|------|------|
| **MCP 服务调用** | 连接公司内部的各种 MCP Server（数据库、实验系统、LIMS 等） |
| **Skill 执行** | 预定义的流程化任务 |
| **参数填充** | 从对话中提取参数，调用对应 Skill |
| **结果格式化** | 将 MCP/Skill 的返回结果转化为用户友好的输出 |

**典型 Skill 示例**：
- "帮我查询某批次的测序质量报告"
- "按照标准流程生成实验报告模板"
- "比对两个基因序列并标注差异"

---

### 3.4 自动化执行 Agent（Automation Agent）

**核心职责**：代码生成和脚本执行（高风险操作，需要隔离）

| 功能 | 说明 |
|------|------|
| **代码生成** | 根据用户需求生成 Python/R 脚本 |
| **脚本执行** | 在沙箱/容器环境中安全运行 |
| **文件处理** | 解析上传的文本/PDF，提取结构化数据 |
| **结果输出** | 生成图表、报告、下载文件等 |

**为什么建议独立？**
- **安全隔离**：代码执行是高风险操作，需要独立的沙箱环境
- **资源隔离**：脚本执行可能消耗大量 CPU/内存，不影响其他 Agent
- **权限分离**：可以单独配置执行权限和文件系统访问范围

## 4. 协作流程示例

### 4.1 简单问答

```
用户："CRISPR-Cas9 的 off-target 效应怎么降低？"
        ↓
主控 Agent → 识别为"知识问答" → 路由到问答 Agent
        ↓
问答 Agent → RAG 检索 → 生成回答 → 返回主控 → 返回用户
```

### 4.2 流程化任务（调用 MCP）

```
用户："帮我查一下批次 B20240601 的测序质量报告"
        ↓
主控 Agent → 识别为"Skill 调用" → 路由到工具 Agent
        ↓
工具 Agent → 提取参数(batch_id="B20240601")
         → 调用 MCP Server(lims.get_sequencing_report)
         → 格式化结果 → 返回
```

### 4.3 复杂自动化（多 Agent 协作）

```
用户："上传了这个 CSV 文件，帮我做差异表达分析并生成火山图"
        ↓
主控 Agent → 拆解任务：
        ├─ Step 1: 文件解析 → 路由到自动化 Agent
        │              ↓
        │     自动化 Agent: 读取 CSV，验证格式，提取表达矩阵
        │              ↓
        ├─ Step 2: 调用分析流程 → 路由到工具 Agent
        │              ↓
        │     工具 Agent: 调用 MCP(desq2_analysis) 获取统计结果
        │              ↓
        ├─ Step 3: 生成可视化脚本 → 路由到自动化 Agent
        │              ↓
        │     自动化 Agent: 生成 Python 脚本 → 执行 → 生成 PNG
        │              ↓
        └─ Step 4: 汇总报告 → 路由到问答 Agent 生成总结
                       ↓
        主控 Agent 汇总所有结果 → 返回用户（图表 + 文字说明）
```

## 6. Skill 设计规范

Skill 是预定义的流程化任务，建议采用 YAML 格式定义：

```yaml
skill_name: "sequence_alignment_analysis"
description: "对上传的序列文件进行比对分析"
category: "bioinformatics"
version: "1.0.0"

# 输入参数定义
parameters:
  - name: "sequence_file"
    type: "file_upload"
    description: "待比对的序列文件（FASTA 格式）"
    required: true
    accepted_formats: [".fasta", ".fa", ".txt"]

  - name: "reference"
    type: "string"
    description: "参考序列 ID 或序列内容"
    required: true

  - name: "algorithm"
    type: "enum"
    description: "比对算法"
    options: ["blast", "muscle", "clustalw"]
    default: "blast"
    required: false

# MCP 工具调用链
mcp_tools:
  - name: "sequence_aligner"
    endpoint: "mcp://bio-tools/align"
    timeout: 300

  - name: "result_visualizer"
    endpoint: "mcp://bio-tools/visualize"
    depends_on: ["sequence_aligner"]

# 输出格式
output_format: "markdown_table"
output_files:
  - name: "alignment_result"
    format: "json"
  - name: "visualization"
    format: "png"

# 权限控制
permissions:
  require_approval: false
  allowed_users: ["bio_team", "bioinformatics_team"]
```

## 7. 文件上传处理

系统支持以下文件类型的上传和处理：

| 文件类型 | 处理方式 | 说明 |
|---------|---------|------|
| **文本文件** | 直接读取 | `.txt`, `.csv`, `.tsv`, `.md` |
| **PDF** | OCR + 文本提取 | 支持扫描版 PDF（需 OCR） |
| **Excel** | 解析为 DataFrame | `.xlsx`, `.xls` |
| **图片** | OCR 识别 | 实验结果图、凝胶电泳图等 |
| **生物数据格式** | 专用解析器 | `.fasta`, `.fastq`, `.vcf`, `.bed` |

### 处理流程

```
用户上传文件
    ↓
文件类型检测 & 格式校验
    ↓
├── 文本/PDF → 文本提取 → 分块 → 向量化 → 存入向量库
├── Excel/CSV → 解析为结构化数据 → 数据预览
├── 图片 → OCR → 文本提取
└── 生物数据 → 专用解析 → 序列/特征提取
    ↓
根据用户请求进行后续处理（问答、分析、可视化）
```

## 8. 开发建议

### 8.1 开发阶段规划

| 阶段 | 目标 | 周期 |
|------|------|------|
| **Phase 1** | 主控 Agent + 问答 Agent（基础 RAG） | 2-3 周 |
| **Phase 2** | 工具 Agent + MCP 连接 + Skill 框架 | 2-3 周 |
| **Phase 3** | 自动化 Agent + 沙箱执行环境 | 2 周 |
| **Phase 4** | 文件上传处理 + 高级功能优化 | 1-2 周 |

### 8.2 安全注意事项

- [ ] 自动化 Agent 必须在 Docker 沙箱中执行代码
- [ ] 敏感 MCP 操作需要二次确认
- [ ] 文件上传限制大小和类型，防止恶意文件
- [ ] API 接口需要身份认证和权限控制
- [ ] 日志记录所有 Agent 操作，便于审计

### 8.3 扩展性考虑

- Skill 采用插件化设计，支持热加载
- MCP Server 配置化，方便新增内部服务
- Agent 间通信采用标准协议（如 MCP 或自定义 JSON-RPC）
- 支持 horizontally scale，各 Agent 可独立部署
